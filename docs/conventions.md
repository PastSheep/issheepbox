# 约定（Conventions）

分支、提交、工作区的统一约定。所有 agent 必须遵守。

## 1. 分支命名

```
<agent-name>/<任务标识>
```

- `<agent-name>`：工作区对应的 agent 名，全小写、连字符分隔，如 `agent-zhang`。
- `<任务标识>`：任务短名，如 `feat-login`、`fix-timezone`。
- 示例：`agent-zhang/feat-login`、`agent-li/fix-timezone`、`agent-wang/docs-workflow`。
- 分支只用于开发与推送；**永不直接推送 main**。

## 2. 提交信息

格式（一行）：

```
<类型>(<范围>): <摘要>
```

| 类型 | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档变更 |
| `refactor` | 重构，不改行为 |
| `test` | 测试 |
| `chore` | 构建、工具、依赖等杂项 |
| `style` | 格式调整，不影响逻辑 |

正文要求（多行）：

```
<类型>(<范围>): <摘要>

- 改了什么：……
- 为什么改：……
- 影响范围：涉及的文件/模块
```

**正文是合并者解决冲突的关键依据，不允许省略。**

## 3. 工作区约定

- 一个工作区 = 一个独立 clone = 一个 agent。
- 工作区内产出物（缓存、临时文件、构建产物）一律由 `.gitignore` 排除，不入库。
- 不要向工作区提交本机专属路径、密钥、凭据。

## 4. 文档约定

- 所有规范/状态文档放 `docs/` 目录，使用 Markdown。
- 状态类文档（任务清单、agent 登记）由合并者维护；规则类文档（本文档、merge-policy）修改需在提交信息中说明动机。
- 文档与代码同库版本管理，保证所有 agent 拿到的是同一份规则。
